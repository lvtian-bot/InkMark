# 依赖管理与升级策略

本文档规范 InkMark 项目的依赖演进、小版本更新与大版本技术升级原则，供开发与 AI 协作时共同遵守。

## 核心原则

- **主动预防，拒绝被动拖延**：严禁采用“等到官方生命周期结束（EOL）或停止维护前一两个月再升级”的被动策略。过度滞后会导致代差累积；一旦遭遇紧急漏洞或高优先级需求，缺乏缓冲时间。
- **生态就绪即主动升级**：只要上游配套工具链（如 bundler、linter 适配插件、测试框架等）正式发布稳定版并完成兼容，就应主动安排平滑升级，小步快跑消除技术债务。

## 升级分类与执行规范

### 1. 范围内的小版本与补丁（Patch / Minor）

- **范围**：现有 semver 范围内的缺陷修复、构建优化、同系列运行时补丁（如 Electron 补丁位）。
- **执行**：可结合日常维护适时更新，执行完整质量门禁 `npm run check` 校验通过后合入。

### 2. 跨大版本升级（Major Upgrade）

- **前置条件**：整条上下游工具链已正式支持（无 beta 依赖阻断，无 linter/编译器断裂）。
- **独立排期与分支**：跨大版本升级属于底层基础设施演进，必须拉取专门的升级分支单独推进，**严禁与日常业务功能或紧急 Bug 修复混在同一个发布包中**。
- **针对性验证**：
  - 编辑器核心（Milkdown / React）：重点回归中文输入法、选区与表格交互、Markdown 解析与序列化。
  - 桌面与打包运行时（Electron / electron-builder）：重点回归窗口状态、快捷键、文件关联以及安装包升级与迁移逻辑。
