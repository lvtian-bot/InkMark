# InkMark 待办

产品出发点、定位与边界见 [product-positioning.md](./product-positioning.md)。

待办记录的任务不代表一定要做，是可以探讨的。如果在实现过程当中会带来更大的问题，或者是说成本大于收益，必须要提出来。

## 记录规则

1. 所有任务必须归入以下五个分类之一：体验与界面、编辑与文件、稳定性与安全、工程与发布、暂不需要。
2. 本次分类迁移完成后，以现有顺序为基准；新增任务一律追加到对应分类的末尾，不插入已有任务之间，不因开始或完成而移动位置。
3. 任务完成后只把 `[ ]` 改为 `[x]`，并在任务末尾按 Obsidian Tasks 格式记录完成时间：`✅ YYYY-MM-DD`。
4. 未完成任务不写完成时间；无法从历史记录确认日期的完成项标记 `✅ 日期待核`。
5. 同一任务只能出现一次。需要调整分类、顺序或新增分类时，先确认再修改。

* [x] 内容安全自动化测试（Vitest） ✅ 2026-08-09
  * 已有 20 个测试，覆盖四类内容安全场景：
    * 标签/模式编辑状态隔离（document-editor-state，3 用例）：按 tab/mode 隔离、陈旧状态不恢复、关闭释放。
    * 外部修改检测与冲突决策（file-conflict-decision，14 用例）：mtime 比较分支、冲突三选一映射、关闭保存/放弃/取消。
    * 冲突差异渲染（conflict-diff，1 用例）：按显示顺序标记增删行。
    * 源码模式大纲与正文提取（source-document，2 用例）：忽略代码块内的标记。
  * 标签增删切换、模式互切的核心保证（编辑状态隔离）由 document-editor-state 覆盖；其数据流转为直白 store 操作，不单独加测，避免引入 DOM 测试基建的技术债。
* [x] 发布质量门禁与工程检查收口 ✅ 2026-08-09
  * 统一 package、lock 和 tag 版本；新增 lint、类型检查、测试、格式检查、构建及分支 CI。
