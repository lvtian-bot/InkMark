- [x] 首页右侧大块同色空白 ✅ 2026-08-14
  - 原因：`toolbar.css` 三档工具栏宽度类写成裸类选择器（`.toolbar-width-wide { max-width: 850px }`），而该档位类同时挂在 `.editor-main` 上供查找面板联动选择器使用，导致整个主内容区被限宽 850px，窗口剩余宽度只剩 body 背景（与首页同色）；编辑模式因正文本就限宽 850 居中而不可见，首页布局与侧栏位置暴露问题。
  - 已修复：三档选择器限定为 `.toolbar.toolbar-width-*` 只作用于工具栏；查找面板的 `.editor-main.toolbar-width-* .find-replace-bar` 联动规则本就以 `.editor-main` 为前缀，不受影响。
- [x] 启动闪屏出现整片标签栏蓝 ✅ 2026-08-14
  - 原因：启动性能优化把窗口启动底色设为浅色标签栏蓝 `#eef4f9`，浅色主题正文区是白色，启动序列变成「白 → 整窗蓝 → 正常」，比原先纯白闪屏更扎眼。
  - 已实现：窗口底色与标题栏按钮色统一收敛到主进程 `chromeColorsFor(themeId)`（浅色底色纯白、深色 `#1e1e2e`）；`theme:syncThemeId` 把主题落盘 userData/theme.json，下次启动在 whenReady 恢复，首帧前底色、原生主题与主题菜单初始勾选不再回落浅色默认。theme-architecture.md 同步点章节已更新。
- [x] 首页最近列表宽度三档设置 ✅ 2026-08-15

- [x] 修复设置与源码模式默认快捷键失效并移除 Alt+E 硬编码 ✅ 2026-08-15
  - 原因：① 设置等快捷键此前缺少前端 DOM 捕获监听，在 Windows 无边框自定义标题栏下原生菜单 accelerator 无法可靠触发；② 快捷键校验排除了 Alt 组合键；③ 默认快捷键 Ctrl+/ 易受输入法标点与系统占用影响，且旧默认值被持久化缓存阻碍更新。
  - 已修复：前端捕获阶段统一拦截与分发 11 个应用功能快捷键；开放 Alt 组合键录制；切换源码模式默认快捷键调整为 Ctrl+E（对齐 Obsidian），加入中文标点与物理键码回捞，并在配置加载时提供旧版默认值的无感自动升级；完全删除 Alt+E 硬编码分支。
- [x] 菜单栏标点快捷键展示与全界面快捷键提示动态对齐 ✅ 2026-08-15
  - 原因：① Electron Accelerator 中标点符号被转为无效键名（如 `Comma`），导致菜单栏设置项缺少快捷键展示；② 状态栏模式切换、设置与标签栏新建等按钮 Tooltip 硬编码或缺少快捷键占位符，无法随个性化配置动态更新；③ 编辑菜单缺少查找与替换入口。
  - 已实现：标点按 Electron 规范直接使用标准字符生成 accelerator；编辑菜单补齐「查找...」与「替换...」项及 IPC 分发；状态栏（源码模式/设置）与标签栏（新建）文案统一改为 `{shortcut}` 占位符并从 Store 动态读取格式化，跟随用户自定义配置即时刷新。
- [x] 菜单栏弹出位置贴合按钮下方边缘 ✅ 2026-08-15
  - 已优化：点击标签栏汉堡菜单按钮时，不再以鼠标光标落点随意弹出，而是获取按钮边界矩形坐标（`rect.left`, `rect.bottom`），统一在按钮正下方靠左边缘对齐弹出（对齐 Chrome 标签页搜索等现代界面规范）。
- [x] 视图菜单能力扩展、工具栏显隐设置与大纲/文件树快捷键 ✅ 2026-08-15
  - 已实现：① 视图菜单新增「工具栏」勾选项、「切换全屏 (F11)」与「保持窗口在最前端」（置顶）支持，不加冗余的开发者工具；② 设置面板「外观」新增「显示工具栏」开关，控制编辑区顶部格式工具栏显隐并持久化；③ 统一快捷键模型新增「切换大纲」（默认 Ctrl+Shift+L）与「切换文件树」（默认 Ctrl+Shift+E），状态栏 Tooltip 与视图菜单自动对齐快捷键提示；④ 支持使用 Ctrl+Tab 与 Ctrl+Shift+Tab 循环切换多文档标签。

- [x] 应用内更新自 v0.1.2 起永远卡在“正在检查更新” ✅ 2026-08-16
  - 根因：启动优化（46e4da4）把 electron-updater 改为运行时原生 `import()` 动态加载，主进程产物是 CommonJS，Node 的 cjs-module-lexer 识别不出其 getter 导出的 `autoUpdater`，解构得到 undefined，更新服务初始化抛 TypeError 且失败 Promise 被缓存，IPC reject 后渲染层无兜底，界面无限转圈；类型声明里有该导出，`npm run check` 与 vitest 的 ESM 互操作均覆盖不到此场景。
  - 已修复：新增 `resolveAutoUpdater` 以 `module.autoUpdater ?? module.default?.autoUpdater` 兜底取值；初始化失败不再缓存 rejected promise；四个更新 IPC 失败统一返回错误状态而非 reject。已在真实 Electron 主进程探针中验证：旧写法解析为 undefined、新写法得到可用 updater。
  - 回归：`resolve-auto-updater.test.ts` 覆盖命名空间/default/getter 三种形态，并以子进程跑真实 CommonJS Node 语义验证可达性。v0.1.2–v0.1.4 已安装版本无法自愈，修复版发布后老用户需手动安装一次。
