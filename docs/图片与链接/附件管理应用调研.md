# 附件管理应用调研

本文只记录 Typora、Obsidian 和 Visual Studio Code 官方文档中明确写出的行为，用于评估 InkMark 的本地 Markdown 图片与附件处理方式。

## 官方资料中的共同做法

### Typora

Typora 将图片作为 Markdown 中的文件路径引用，支持相对路径。插入本地图片时，可以配置把图片复制到指定目录，并同步更新正文中的 `src` 路径。它还提供单张或全部图片的「移动」和「复制」操作：文件移动或复制后，会更新 Markdown 中的图片引用；复制会保留原文件。

Typora 1.3 的官方更新说明还明确记录了一个特殊规则：如果用户配置了 `${filename}.assets` 这类与文档名绑定的图片目录，在 Typora 文件树中重命名或移动当前文档时，程序会弹框协助把附件目录一起改名或移动，并更新当前文档中的图片引用。该说明还注明 macOS 上在应用外重命名或移动也可触发。该说明是版本更新文档中的功能描述，不等同于当前版本实测，也不足以推断普通「另存为」会自动复制全部已引用图片。

来源：[Images in Typora](https://support.typora.io/Images/)、[Typora 1.3 更新说明](https://support.typora.io/What's-New-1.3/#auto-move-image-folder)。

### Obsidian

Obsidian 允许配置附件存放位置，例如当前文件同目录、当前目录下的子文件夹或其他指定位置。它支持 Markdown 图片链接和自身的嵌入链接，并可在重命名文件时自动更新内部链接。官方设置文档没有把附件目录与笔记文件名绑定为唯一规则，也没有明确说明普通「另存为」会复制已引用附件；Obsidian 的核心模型是同一 Vault 内管理文件和链接，而不是桌面编辑器式的独立文档另存。

来源：[Settings](https://obsidian.md/help/settings)、[Internal links](https://obsidian.md/help/links)。

### Visual Studio Code

VS Code 在粘贴或拖入工作区外的图片时，默认会把图片复制到工作区，目标位置由 `markdown.copyFiles.destination` 配置，并在 Markdown 中写入新路径。它还提供文件移动或重命名时的 Markdown 链接更新，覆盖 Markdown 文件、图片和目录；该功能默认关闭，可设置为提示或自动执行。官方文档没有说明另存 Markdown 文件时会自动复制所有已引用图片。

来源：[Markdown and Visual Studio Code](https://code.visualstudio.com/Docs/languages/markdown)。

## 对 InkMark 的启示

可借鉴的重点是维护正文中的实际图片引用；是否采用「文档名加 `.assets`」这类约定，则取决于应用的附件组织方式。结合 InkMark 的本地文档定位，建议如下：

- 插入图片时，复制到确定的附件位置，并把正文写成相对路径。
- 移动或复制图片时，同时更新正文引用；不能只搬文件而留下旧路径。
- 同目录仅改文档名时，原有相对图片路径通常仍然有效，无需复制图片；跨目录另存或移动时，才需要按正文逐条解析本地图片引用，解析出真实源文件后再复制附件，而不是只猜测一个附件目录。
- 对没有找到的引用保留正文并给出提示，不能静默删除或伪造附件。

对 InkMark，这里的设计建议是：跨目录另存时读取源文档中实际引用的本地图片，逐一解析并复制到目标文档可访问的位置，同时保持或重写相对路径；复制失败时明确提示。同目录改名不必为了附件复制而改写正文。是否把跨目录另存的目标附件目录改成新文档名、以及是否更新正文路径，需要作为单独的产品决策确认。现有官方资料足以支持「按实际引用处理」这一原则，但不足以证明某个应用的 Save As 具体实现。
