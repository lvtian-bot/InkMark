# 文件树跟随标签页方案

本文记录文件树如何跟随标签页活动文档的规则与实现要点。规则已讨论确定，行为演示一节是验收依据。

## 背景

文件树首版已完成：打开文件夹后可以折叠浏览，点击 `.md` 文件复用既有流程打开为标签。但树的根目录目前只在用户明确「打开文件夹」时设置，与标签页完全没有联动：新打开文件后树仍停在旧文件夹，正在看的文档在树里找不到。

目标是让文件树始终显示活动文档所在的文件夹，树与正在查看的文档保持一致。

## 规则

全案只有一条规则、一个触发点，不引入「根的来源」「是否锁定」这类状态。

触发时机：活动文档的路径发生变化。两类动作都归结为这一个事件：

- 新打开：打开对话框、最近文件、拖入、文件关联、启动参数、点击树内文件。
- 切换标签页。

触发后的处理：

1. 文档没有路径（新建未命名）→ 不动树。
2. 文档在树当前显示的文件夹里面 → 不换根，自动展开它所在的目录链并高亮该文件。
3. 文档在树当前文件夹之外（或树还没有根）→ 换根：会话记录里如有曾经显示过且能覆盖该文档的根，切回其中最近显示的一个并恢复其展开状态；否则切到该文档所在的文件夹。

另有两条独立规则：

- 用户明确「打开文件夹」直接设置根，优先于跟随规则。此刻活动文档没有变化，跟随不会立刻触发，树稳定显示新打开的文件夹；之后活动文档一旦变化，跟随规则接管。
- 展开状态按根记录（离开时保存、进入时恢复），在不同目录的文档之间来回切换时不会每次都从全部收起开始。

另存为不单独处理：保存后路径变化，自然走上面的触发与处理。启动参数打开多个文件时，以第一个文件所在的文件夹作为初始根。

跟随只更新根目录，不自动展开或收起文件树面板本身；面板是否可见仍由用户控制（设置、菜单、状态栏入口）。

## 行为演示

1. 打开文件夹 `F` → 树显示 `F`。
2. 打开 `F` 子文件夹里的 `a.md` → 树保持 `F`，自动展开目录链并高亮 `a.md`。
3. 从最近文件打开 `F` 外面的 `b.md` → 记录中没有能覆盖它的根，树切到 `b.md` 所在的文件夹。
4. 切回 `a.md` 标签 → 记录中的根 `F` 能覆盖 `a.md`，树回到 `F`，恢复离开前的展开层级，`a.md` 高亮。
5. 新建未命名文档 → 树保持不变。
6. 把 `a.md` 另存为到 `F` 之外 → 树切到新位置所在的文件夹。

## 实现要点

- 共享层（`src/shared/`）：新增路径包含判断的纯函数，处理 Windows 盘符大小写、两种分隔符、结尾分隔符等边界情况，配单元测试。
- 文件树钩子（`useFileTree`）：新增协调逻辑，唯一触发点是活动文档路径；新增会话级小字典记录「根 → 展开集合」与根的显示先后。
- 定位文件：需要从根出发沿文件所在目录链逐级加载目录列表，这是方案中唯一的异步链，集中在一个函数内。
- 不动的部分：标签数据模型、进程间接口（列目录接口本来就接受任意路径）、工作区监听（监听器绑定根目录，根变化时既有订阅 effect 会自动重新监听）。

## 不在本次范围

- 多根 / 多文件夹同时显示。
- 树内新建、重命名、删除等改写文件系统的操作（已在待办中另行记录）。
- 根目录与展开状态跨会话持久化（标签会话恢复本身尚未支持）。

## 验证

- 单元测试：路径包含判断；协调决策的各分支（在根内、根外、无根、未命名文档、覆盖根恢复、另存为）。
- 手工：按行为演示逐条走一遍，重点观察两个不同目录文档来回切换时的展开恢复。
- 完整质量门禁 `npm run check`。
