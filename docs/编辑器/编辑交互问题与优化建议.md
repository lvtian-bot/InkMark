# 编辑交互问题与优化建议

2026-11-19，基于 InkMark 0.2.9 的源码版本 `434da34`。重点覆盖打开已有 Markdown 后修改列表、任务、段落和选区的 Windows 桌面场景。优先级按误改内容的影响、操作是否容易发现、事后能否察觉来排。

## 试用版验证重点

- 对顶层单项、第二项以及已完成任务之后的未完成项分别按行首退格，观察文字左边缘、相邻复选框和撤销结果。嵌套项应一次退出一级。
- 可直接用工具栏段落符号（¶）“转为正文”处理已有标题或列表。批量转清单时，重点检查选择结束在下一行开头的情况。
- 父项有明细时，分别试按 Enter 和“删除整行”。检查明细的内容、层级与勾选状态。表格中用 Enter 向下、Tab 向右，最后一行验证续行落点。
- 跨格式选择时，可试着将一个标题和它下面的列表一起转为正文，或仅转换编号列表的第一项。后者应保留第二项的编号和列表结构。源码模式还可验证带结尾井号的标题与跨行引用里的加粗切换。

## 初次排查：普通按键可能误改内容

| 操作                             | 已复现的结果                                                                                                                                 | 建议的验收标准                                                                                                                               |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 在第二个列表项的第一个字前按退格 | 所见即所得下，第二项的圆点消失，文字仍缩进，成为第一项里的第二段。第一项已勾选、第二项未勾选时，第二个复选框也会消失，文字归入已完成项。     | 在顶层，当前项转成独立正文，与正文左边缘对齐。在子列表中，一次只退一级。光标留在原文字前，前后事项的内容和勾选状态正确。一次撤销恢复原结构。 |
| 在任务项开头按 Delete            | 任务文字为“😀开会”或“𠮷野”时，首字符只删掉一半，文档内留下无效字符。普通列表第二项行首按同一个键，还可能将这项并入上一项，右边第一个字仍在。 | 光标右边有文字时，按一次删除一个完整的可见字符。对普通汉字、生僻字、表情和组合字符分别验证，并检查任务状态与保存重开结果。                   |
| 在父项上执行“删除整行”           | 父项下面有两条明细时，父项连同两条明细一起消失。段内用换行分开的两行文字也可能作为一个段落一起删除。源码模式按文本行删除。                   | 无选区时只删光标所在的逻辑行。保留未选中的子项和同段其他行；对于自动折行的一段，按实际换行符界定行。                                         |

第一项的根因已定位。列表退格逻辑比较了列表项内容的起点与首段文字的起点，两者相差一个位置。因此本应优先执行的退出逻辑没有接手，默认按键处理接管了退格。单独一个已有顶层列表项恰好能被默认行为正确处理，单测里直接传入“位于首段”的结果也绕过了这个错误。任务项的 Delete 则固定删除一个 UTF-16 编码单位。“删除整行”主动将删除范围扩到了整个列表项。[列表按键](../../src/renderer/src/plugins/list-keymap.ts) · [现有退格测试](../../src/renderer/src/plugins/list-keymap.test.ts) · [删除整行](../../src/renderer/src/components/Editor.tsx)

## 初次排查：格式操作及选区

| 操作                             | 当前行为                                                                                                                                                      | 优化建议                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 把已有列表项或标题还原成正文     | 所见即所得下，在已有简单列表上再点“无序列表”，仍是列表；在二级标题上再点 H2，仍是二级标题。源码模式却会把完全匹配的前缀移除。工具栏也没有直接转成正文的按钮。 | 优先让再次点同一列表按钮可以取消列表，并提供可发现的“转为正文”操作。对同一选择范围，两种模式产生一致的文档结构。             |
| 选三行改成清单                   | 源码模式下选中三行，点无序列表或任务列表，只改第一行，选区随后消失。在所见即所得下，选中多个已有列表项再点任务列表，命令也只修改选区起点所在项。              | 按选区覆盖的各行或列表项批量转换，保留选区。选区恰好停在下一行行首时，排除该未选中的行。                                     |
| 修改其他工具生成的列表           | 源码模式下，在 `* 事项` 上点无序列表会变成 `- * 事项`；在缩进两格的 `- 子项` 上操作，会在原缩进前再加标记。项目本身能解析这些写法。                           | 识别原有的列表类型和层级再做切换，覆盖 `-`、`*`、`+`、编号和任务项。普通文字前原有的空格与列表结构分别处理。                 |
| 给同一段选中文字连续加粗、加斜体 | 源码模式加粗后，选区折叠到文字开头，无法直接给同一段文字叠加斜体。选区从已有加粗内部跨到外部时，命令会机械插入两端标记，可能留下交错的星号。                  | 格式切换后维持原文字选区。跨已有格式时按选区实际内容合并或移除标记。Obsidian 1.14 的公开示例专门展示了跨加粗边界的处理结果。 |

核对入口见[双模式格式命令](../../src/renderer/src/editor-commands.ts)、[工具栏](../../src/renderer/src/components/Toolbar.tsx)、[任务列表转换](../../src/renderer/src/plugins/task-list.ts)和[源码格式测试](../../src/renderer/src/editor-commands.test.ts)。跨选区参考 [Obsidian 1.14 桌面版说明](https://obsidian.md/changelog/2026-10-05-desktop-v1.14.4/)。

## 与成熟编辑器对照

- **列表格式应当可以主动取消。** Obsidian 1.15.1 的无序列表切换命令会检查整个选区。当所选各行都是无序列表时，命令移除列表标记，保留原有缩进前缀。因此一条没有额外缩进的顶层事项可以一步还原成正文。InkMark 把“无序列表”放在工具栏上，所见即所得下再次点击却无法取消已有单项。建议让这个已有入口支持取消，并验证包含子项或多段文字的选择范围。
- **横着填表和竖着填表都需要顺手。** 在三列两行的表格中，从第一行第二列按 Enter，InkMark 移到第一行第三列，与 Tab 完全相同。Obsidian 1.15.1 的 Markdown 表格用 Tab 横移，Enter 进入下一行同一列。建议 InkMark 也采用这一区分，末行按 Enter 新增行并保留列位置，Shift+Enter 继续用于单元格内换行。[InkMark 表格按键](../../src/renderer/src/plugins/table-enter-keymap.ts) · [现有跳格测试](../../src/renderer/src/plugins/table-enter-keymap.test.ts)

- **取消格式与结束输入是两个操作。** Word 明确区分了选中已有条目后点列表按钮取消格式，以及在末尾连按回车后接着写正文。Typora 还提供独立的正文段落命令。以 InkMark 打开现成文档、修改其中一项的场景看，取消已有格式值得成为直接可用的操作。[Word 列表操作](https://support.microsoft.com/en-us/word/create-a-bulleted-or-numbered-list-in-word-for-mac) · [Typora 段落命令](https://support.typora.io/Shortcut-Keys/)
- **嵌套列表的回车要考虑已有子项。** InkMark 在有子项的父项文字末尾按 Enter，会创建空的同级项，原有子项归到新项下面。Obsidian 1.15 的智能列表在展开的父项末尾回车，会创建第一个子项；折叠时则在该项下面新建同级项。建议 InkMark 优先处理日常可见的展开场景，使父项继续带着自己的明细。[Obsidian 1.15 桌面版说明](https://obsidian.md/changelog/2026-11-02-desktop-v1.15.0/)
- **正文回车可以维持现有分工。** InkMark 所见即所得下 Enter 新起段落，Shift+Enter 段内换行，与 Typora 一致。Obsidian 的默认编辑模式是实时预览，按 Enter 在 Markdown 里插入一行，段落用空行分隔。InkMark 以办公人员直接编辑已排版内容为主，采用现有段落逻辑有明确理由。[InkMark 换行说明](../line-break-mode.md) · [Typora 编辑快捷键](https://support.typora.io/Shortcut-Keys/) · [Obsidian 编辑模式](https://obsidian.md/help/edit-and-read) · [Obsidian 段落说明](https://obsidian.md/help/syntax)

## 原版本复验“圆点没了，前面还有空格”

| 起始文档和动作                        | 所见即所得                                 | 源码模式                                                         |
| ------------------------------------- | ------------------------------------------ | ---------------------------------------------------------------- |
| 打开只有一行的 `- 事项`，在“事”前退格 | 转成顶层正文，首字前没有额外空格           | 得到 `事项`                                                      |
| 打开连续两项，在第二项首字前退格      | 第二项变成上一项中的段落，继续显示列表缩进 | 无序标记和分隔空格变成两个实际空格。有序项 `2. ` 会变成三个空格  |
| 从只有一项的列表末尾按回车退出        | 第一次生成空项，再按一次退出顶层列表       | 从 `- 事项` 开始，第二次回车会先插入空行，第三次才移除空列表标记 |

所见即所得里的结构性缩进、源码里由编辑器写入的空格，以及文字原来就有的空格，外观可能相近。前两种都能在原文没有额外空格的情况下出现。验收时应同时检查文字、段落归属、保存后的 Markdown 和撤销结果。[所见即所得编辑器](../../src/renderer/src/components/Editor.tsx) · [源码编辑器配置](../../src/renderer/src/components/SourceEditor.tsx) · [CodeMirror 的 Markdown 按键](https://codemirror.net/docs/ref/#lang-markdown.markdownKeymap)

## 验证范围

InkMark 的按键在本地编辑器内核中执行，用示例文档核对段落结构、勾选属性、文字及 Markdown 输出。“删除整行”和源码格式操作使用当前项目命令。另运行了列表按键、列表标记、表格跳格和格式命令四组现有测试，39 项通过。桌面窗口里的光标视觉位置、中文输入法和实际文件保存重开未逐项回放。

Obsidian 对照依据为本机 Windows 桌面版 1.15.1 的命令与键位实现，以及官方帮助和版本说明。菜单命令和表格键位按该版本记录；对于列表行首的第一次退格，缺少该版本完整界面回放，无法仅凭两款产品都用了 CodeMirror 推定实际结果一致。
