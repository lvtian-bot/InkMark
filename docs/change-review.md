# 外部改动审阅（需求）

本文把 [`product-positioning.md`](./product-positioning.md) 中「面向 AI 的文件协同——逐步提供清晰的变化审阅能力」这一长期方向，细化成具体的需求，作为后续设计与开发的依据。本文只讲需求：用户在什么场景下、能看到什么、能做什么，不涉及实现方式。

## 背景与现状

InkMark 的定位是「AI 或其他工具在外部处理 Markdown 文件，InkMark 是人查看、简单编辑和审阅这些文件的桌面界面」。AI 修改文件是日常高频场景，但目前用户对「AI 改了什么」缺乏感知和掌控：

- **干净文档被外部改动**（用户自己没改过）：当前是**静默自动刷新**，内容在用户不知情时被换成新版。
- **用户有未保存改动、文件又被外部改动**：当前弹冲突框，但只能「整体用磁盘版本 / 整体保留自己版本 / 取消」三种**整体**选择。

三个痛点：

1. 看不出 AI 到底改了什么。
2. 只能整体接受或拒绝，没法挑着接受——AI 改了五处，用户可能只想接受三处，目前做不到。
3. 静默刷新让人不知道内容已经变了，可能继续在旧印象上操作。

## 目标

外部（AI 或其他工具）改了文件后，用户能在编辑区里清楚看到每一处改动，并能逐块接受或拒绝；外部改动不静默、也不自动刷新，而是给出提示，由用户选择「直接替换」还是「逐项审阅」。

## 外部改动发生时的选择（2026-08-24 修订）

检测到外部改动后不自动刷新，由用户决定处理方式：

1. **干净文档（自己没改过）**：编辑区顶部提示「文件已被外部更新」，提供**直接替换**（加载磁盘新版）与**逐项审阅**（进入审阅视图）两个动作。
2. **有未保存修改的文档**：弹冲突对话框，在「使用磁盘版 / 逐项审阅 / 保留并覆盖 / 取消」中选择。
3. **已在审阅中**：审阅是持续状态，新的外部改动继续静默进入审阅，不打断正在逐块处理的用户。

不设全局「审阅模式」开关，审阅由用户在每次外部改动时按需进入。

## 用户场景

- **场景 A（逐项审阅 + AI 润色）**：文件被外部润色后，用户在提示上选择逐项审阅。编辑区把每一处改动标出来，用户逐块接受或拒绝，最后合并出自己想要的版本。
- **场景 B（干净文档 + 外部改动）**：文件被外部改了，编辑区顶部冒一条「文件已被外部更新」。用户点「直接替换」把内容换成新版本，不点则继续显示当前内容；提示期间若文件再次被外部改动，替换时加载到最新版本。
- **场景 C（自己也改了 + 外部也改了）**：用户有未保存的改动，外部又改了同一个文件。在冲突对话框中选择逐项审阅，在「自己的改动」和「外部的改动」之间逐块选择，解决冲突。
- **场景 D（审阅结束自动写回磁盘，2026-09-04 修订）**：审阅结束（最后一块处理完，或退出审阅时表态）后，合并出的最终内容由审阅流程自动写回磁盘，文档回到干净状态。用户不需要按保存，也不留下「有未保存改动」的悬置状态。

## 期望的用户体验

### 形态：编辑区内联审阅，不弹窗

类比 Word 的修订模式，或 VS Code 的 diff 审阅。改动直接画在正文里，而不是用一个单独的弹窗承载。

- **删除的内容**：划线、红色，可「接受删除」或「恢复」。
- **新增的内容**：底色或下划线、绿色，可「接受」或「拒绝」。
- **每个改动块**（一处连续的改动）旁边有接受 / 拒绝操作。
- 改动很多时弹窗装不下也看不清，所以**必须在编辑区里**展示，这是本需求的核心取舍。

### 粒度：按行（2026-09-04 修订）

以行为决策单位：一行内的任何改动，整行构成一个改动块（与 Git / VS Code 的行级 diff 一致），连续改动的多行合并为一个块，每块一组接受 / 拒绝操作。初版按词对比会把 AI 润色的一段话拆成十几个待决块，逐块处理反而不堪其扰，实际体验后调整为整行粒度；行内具体哪个词变了不再单独区分，是已知的取舍。

### 大段与结构性改动

AI 改 Markdown 时，常常不只改字，而是改结构——重排段落顺序、改标题等级、移动整段。纯文本对比在这种情况会显示成「一大段被删 + 一大段新增」。

按 Git 的标准做法处理，不做特殊的「移动识别」：**删除的块**按删除展示（红）、**添加的块**按添加展示（绿），各自配接受 / 拒绝按钮，由用户分别决定。另外能**折叠未变化的区域**，把注意力集中在改动上。

### 编辑模式：只在源码模式提供（2026-08-24 决定）

审阅视图只在源码模式提供。外部改动进入审阅时自动切换到源码模式；审阅期间锁定模式切换，处理完待决块或确认退出审阅后自动回到所见即所得模式。所见即所得模式下的内联审阅不再列入计划。

### 审阅中的编辑：锁定，不并存（2026-09-04 修订）

审阅期间**锁定编辑**：编辑区有待决块时用户不能修改文档内容，审阅就是纯粹的一件事——逐块接受或拒绝，想编辑先处理或退出审阅。

初版允许「审阅中正常编辑」，配套一条隐式规则：用户编辑触到某块附近，该块静默视为已被处理。实际使用中这条规则完全不可感知——块悄悄消失，用户只觉得「东西怎么没了」。隐式规则带来的困惑超过边编辑边审阅的便利，因此改为锁定，用明确的两步（处理完 / 退出）换取可预期的行为。

- **锁定范围**：仅「有待决块」时锁定。块清零后立即写回磁盘并结束审阅会话，用户可继续正常编辑；之后的新外部改动重新回到提示流程。
- **已知取舍**：用户正在输入时新一批外部改动入库会锁定输入，打字被打断（交互细节留待实测调整）。
- **持续审阅保留**：AI 在外部继续改文件时，新改动继续静默进入审阅，用户按自己的节奏处理，不要求一次性清空。

## 合并与写回磁盘：审阅结束自动保存（2026-09-04 修订）

审阅决定不悬空、不依赖用户补一次保存，审阅结束的那一刻结果直接写回磁盘：

- **有待决块时禁止一切写入**：保存、另存为与自动保存一律拦下并提示（未决块的语义还没定下来，此时写入等于隐式「全部接受」）。
- **块清零即自动写回磁盘一次，并结束审阅**：逐块处理完最后一块、或点「全部接受 / 全部拒绝」（两者都先弹确认）的瞬间，审阅流程把合并结果写回磁盘并结束审阅会话，文档回到干净状态、工具条消失。这是执行用户的逐块决策，属于审阅流程自身的收尾，不受自动保存开关影响（不是基于时间或输入的自动保存）。每批外部改动只写一次磁盘，不随逐块操作递增。
- **全部接受 / 全部拒绝 = 终局操作，需先确认**：这是对整批外部改动的终局决定，先弹确认框，确认后执行、写回磁盘、审阅会话当场结束——不再有单独的「退出审阅」动作。全部拒绝的确认框写明后果（当前内容会覆盖磁盘上的外部修改）。
- **退出审阅需要表态**：还有未决块时点「退出审阅」，先弹窗三选——「全部接受并保存 / 全部拒绝并保存 / 继续审阅」。全部拒绝并保存 = 用手里的版本覆盖磁盘上的 AI 版本（拒绝的本意，但磁盘内容会被覆盖，弹窗须写明后果）。不存在静默退出；块清零后会话已经自动结束。
- **脏文档路径**：冲突弹窗进入审阅的文档，写回磁盘时连同用户既有的未保存修改一起写入——这些修改已经随逐块审阅被用户整体看过一遍。
- **关闭标签 / 关闭窗口**：有未决块时确认「仍要关闭 = 丢弃全部审阅决定（含已接受但尚未写回磁盘的部分），重新打开时看到的是磁盘上的 AI 版本」；已接受但尚未写回磁盘的改动随标签一起丢弃。写回磁盘后（块清零）关闭走正常流程，文档干净、无打扰。
- **崩溃 / 断电等异常中断**：已接受但尚未写回磁盘的改动会丢，磁盘停留在上一版（写入是原子的，不会出现半个文件）。这与所有编辑器一致，不额外做恢复。

一句话闭环：外部改动 → 进入审阅（锁定编辑）→ 逐块处理 → 处理完成自动写回磁盘 → 文档与磁盘一致、干净退出。全程没有静默决定，没有需要用户补做的保存。

## 设计与实现（2026-08-24 定稿）

实现入口在 `src/renderer/src/review/`，关键机制与取舍：

- **投影模型**：编辑器内容永远是「已接受投影」——已决定的块物化进文档，未决块只存在于装饰层（删除侧旧文本在真实文本上标红划线，新增侧文本用 widget 画在插入点，不进入文档）。`sourceContent` 单一真源与保存流程完全不感知审阅。
- **基线快照**：每个标签页保存最近一次确认过的磁盘内容（打开、保存、另存、重载、冲突「保留并覆盖」、入库时更新）；外部增量 = diff(快照, 最新磁盘版)，与用户未保存的编辑无关。
- **按行 diff**：以「整行（含换行符）」为 token 走 jsdiff `diffArrays`，一行内的任何改动整行成一个决策块。初版为按词 diff（自研分词 + `diffArrays`，因 jsdiff 自带的 `diffWords` 会把连续中文当作一整个 token），按词产生的碎片块在实际使用中过细，2026-09-04 改为按行。
- **Git 式变更块**：相邻的删除行与新增行属于同一个替换块，共用一次接受或拒绝决定；纯删除块的操作按钮固定在删除内容的可见末尾，不能落到下一行或折叠区域而看似消失；新增侧 widget 位于块尾（后方未变化区间首行行首），该行同样保持可见、折叠从其下一行开始——CodeMirror 的块替换装饰不渲染落在区间起点的 point widget，起点行被折叠会让绿色新增整体消失。
- **锁定编辑**（2026-09-04 修订，取代原「用户编辑优先」）：有待决块时编辑器只读，不存在用户编辑与未决块的冲突；锚定容错保留——AI 再次改写同一未决区域、导致旧侧文本已不在 buffer 时，改为重新计算当前正文到最新磁盘版的差异，不能把该块静默视为已处理。
- **进入方式**：干净文档经提示条「逐项审阅」进入，脏文档经冲突弹窗「逐项审阅」进入；「直接替换 / 使用磁盘版」走既有重载流程。无全局审阅开关。
- **审阅会话**：进入审阅即开启一个会话，工具条在有待决块时显示；用户点「退出审阅」须对剩余改动表态（见「合并与写回磁盘」），或者处理完最后一块后自动写回并结束会话。会话结束后新的外部改动重新提示用户选择。
- **审阅结束自动保存**（2026-09-04 修订）：块清零由审阅流程走现有保存路径写一次磁盘（此时已无未决块，天然不触发禁保存拦截），成功后磁盘快照与 mtime 同步前移；写入失败按既有保存失败处理（提示用户），文档保持审阅结果并标记「有未保存改动」，下次保存重试。
- **持续审阅**：AI 再次写入文件时，新出现且不重叠的改动追加到现有未决块；若 AI 再次改写同一未决区域，则重算当前正文到最新磁盘版的差异。入库过程不打断用户，已有未决块不能因重复事件、标签切换或锚定失败而静默消失。
- **撤销**：接受/拒绝不进入撤销历史——块状态不参与编辑器的历史回滚，混入历史会出现「文本撤销了、块状态没撤销」的错位。
- **已知取舍**：新增侧文本以 widget 呈现，不带语法高亮、不参与选择复制；用户刚拒绝过的区域若被 AI 再次重写，会以新块重新出现（未决块永远从最新磁盘态重推）；大段结构改动按「删除 + 新增」展示，不做移动识别（与边界一致）。

## 不做什么（边界）

- **不内置 AI**：AI 始终在外部，InkMark 只审阅它的产出，不自己调用模型。
- **不做 Markdown 结构感知 diff**：只做文本对比；结构性大改动的展示不完美是已知取舍，不在本需求解决。
- **不做版本历史 / 快照**（已在「暂不需要」）。
- **不做改动历史的长期存档**：第一版的「点开回看」只针对最近一次外部改动，不保留多次改动的可回溯历史。
