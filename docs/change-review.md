# 外部改动审阅（需求）

本文把 [`product-positioning.md`](./product-positioning.md) 中「面向 AI 的文件协同——逐步提供清晰的变化审阅能力」这一长期方向，细化成具体的需求，作为后续设计与开发的依据。本文只讲需求：用户在什么场景下、能看到什么、能做什么，不涉及实现方式。

## 背景与现状

InkMark 的定位是「AI 或其他工具在外部处理 Markdown 文件，InkMark 是人查看、简单编辑和审阅这些文件的桌面界面」。AI 修改文件是日常高频场景，但目前用户对「AI 改了什么」缺乏感知和掌控：

- **干净文档被外部改动**（用户自己没改过）：当前是**静默自动刷新**，内容在用户不知情时被换成新版。
- **用户有未保存改动、文件又被外部改动**：当前弹冲突框，但只能「整体用磁盘版本 / 整体保留自己版本 / 取消」三种**整体**选择。

三个痛点：

1. 看不出 AI 到底改了什么。
2. 只能整体接受或拒绝，没法挑着接受——AI 改了五处，用户可能只想接受三处，目前做不到。
3. 静默刷新让人不知道内容已经变了，可能继续在旧印象上操作。

## 目标

外部（AI 或其他工具）改了文件后，用户能在编辑区里清楚看到每一处改动，并能逐块接受或拒绝；不开启审阅时，外部改动不静默、也不自动刷新，而是给出提示，由用户点击后再刷新。

## 两种工作状态

外部改动发生时，行为取决于是否处于「审阅模式」：

1. **默认状态（未开启审阅）**：外部改动后，**不自动刷新**，给出**轻量提示**；用户点击后才加载磁盘上的新版本。不静默，把刷新的时机交给用户。
2. **审阅模式（开启）**：外部改动后，**不直接刷新**，而是进入审阅视图，让用户逐块决定每一处改动的去留。

审阅模式通过界面上的「审阅模式」按钮开启（**位置倾向状态栏**，与源码模式、大纲入口等模式类开关放在一起，常驻、好点；若实际体感不合适也可放工具栏）。开启后对所有打开的文件生效。

## 用户场景

- **场景 A（审阅模式 + AI 润色）**：用户开启了审阅模式，AI 在外部润色了文档。切回 InkMark 时，编辑区把每一处改动标出来，用户逐块接受或拒绝，最后合并出自己想要的版本。
- **场景 B（默认状态 + 外部改动）**：用户没开审阅模式，文件被外部改了。编辑区顶部冒一条「文件已被外部更新，点击重新加载」；用户点击后才把内容换成新版本，不点击则继续显示当前内容。提示期间若文件再次被外部改动，点击时加载到最新版本。
- **场景 C（自己也改了 + 外部也改了）**：用户有未保存的改动，外部又改了同一个文件。进入审阅，在「自己的改动」和「外部的改动」之间逐块选择，解决冲突。
- **场景 D（审阅结果落回）**：审阅完成，合并出的最终内容写回文档，并标记为「有未保存改动」，下次保存时覆盖磁盘。

## 期望的用户体验

### 形态：编辑区内联审阅，不弹窗

类比 Word 的修订模式，或 VS Code 的 diff 审阅。改动直接画在正文里，而不是用一个单独的弹窗承载。

- **删除的内容**：划线、红色，可「接受删除」或「恢复」。
- **新增的内容**：底色或下划线、绿色，可「接受」或「拒绝」。
- **每个改动块**（一处连续的改动）旁边有接受 / 拒绝操作。
- 改动很多时弹窗装不下也看不清，所以**必须在编辑区里**展示，这是本需求的核心取舍。

### 粒度：按词

一行里只改了某个词，只高亮那个词，不把整行标红标绿。这样能看清「到底改了哪里」。

### 大段与结构性改动

AI 改 Markdown 时，常常不只改字，而是改结构——重排段落顺序、改标题等级、移动整段。纯文本对比在这种情况会显示成「一大段被删 + 一大段新增」。

按 Git 的标准做法处理，不做特殊的「移动识别」：**删除的块**按删除展示（红）、**添加的块**按添加展示（绿），各自配接受 / 拒绝按钮，由用户分别决定。另外能**折叠未变化的区域**，把注意力集中在改动上。

### 两种编辑模式都要支持

所见即所得模式、源码模式都能进入审阅。用户当前在哪个模式，就在哪个模式里看到审阅视图，不强制切换。

### 审阅中的编辑

审阅期间**允许正常编辑**。审阅不是阻断编辑的状态，而是一层叠在文档之上的待办：用户既能逐处接受 / 拒绝 AI 的改动，也能直接在文档里编辑自己的内容。理由是 AI 可能在持续改文件，审阅常常是一个长时间的工作状态，锁定编辑会让用户无事可做。

- 用户的编辑**即时生效**，不会变成待决项。
- 当用户直接编辑了某处尚未决定的 AI 改动所在区域时，以用户的编辑为准，那处 AI 改动视为已被处理。
- 审阅是持续状态：AI 在外部继续改文件时，新改动会继续进入审阅，用户按自己的节奏处理，不要求一次性清空。

## 合并与落回

- 审阅结果（用户在各改动块上的取舍）合并成最终内容，写回当前文档。
- 合并后的文档标记为「有未保存改动」——因为结果既可能不等于磁盘版本，也可能不等于原来的本地版本，需要由用户保存来覆盖磁盘。
- 保存走现有的保存流程。

## 不做什么（边界）

- **不内置 AI**：AI 始终在外部，InkMark 只审阅它的产出，不自己调用模型。
- **不做 Markdown 结构感知 diff**：只做文本对比；结构性大改动的展示不完美是已知取舍，不在本需求解决。
- **不做版本历史 / 快照**（已在「暂不需要」）。
- **不做改动历史的长期存档**：第一版的「点开回看」只针对最近一次外部改动，不保留多次改动的可回溯历史。
