# 文件导航

## 职责与边界

提供普通文件夹浏览、基础文件操作、活动文件定位、最近打开与星标。文件树支持在文件夹内新建文档、重命名文件、把文件或文件夹移入系统回收站；打开、保存和正文状态仍由文档模块负责。文件树是普通文件管理入口，不扩展为知识库结构。

## 当前实现与状态

- `src/renderer/src/hooks/useFileTree.ts` 保存根目录、目录缓存、展开及加载状态，`components/FileTree.tsx` 显示目录条目并通过右键菜单发起基础操作。
- `src/main/index.ts` 读取单层目录；`src/shared/workspace-tree.ts` 过滤隐藏项，显示目录及全部可打开文档（扩展名白名单见 `src/shared/openable-document.ts`：Markdown 与常见纯文本/代码文件），并默认隐藏 `node_modules`、`__pycache__` 两类依赖缓存目录，目录优先排序。
- 基础操作的文件系统实现在 `src/main/workspace-file-ops.ts`：新建空文档不覆盖既有文件，重命名先显式拦截同名目标（Windows 上 `rename` 会静默替换），IPC 通道为 `workspace:createDocument`、`workspace:renameFile`、`workspace:trash`。文件名规则与操作结果类型在 `src/shared/workspace-file-name.ts`，按 Windows 规则校验禁止字符、保留名与结尾点空格。
- 操作编排（名称输入、删除确认、错误提示与打开标签同步）在 `App.tsx`；受影响标签的判定在 `src/renderer/src/file-tree-actions.ts`。重命名后打开标签的路径、文件名与磁盘基线同步更新，未保存修改保留；删除后受影响标签静默关闭。进行中审阅（审阅会话或未决审阅块）的文件不允许重命名或删除，须先完成或放弃审阅。
- 活动文件跟随使用 `src/shared/file-tree-follow.ts` 的纯决策；当前会话记忆访问过的根及展开状态，必要时切换根并展开到活动文件。
- 主进程持久化最近记录，`src/shared/recent-items.ts` 提供规范化逻辑；`StartPage.tsx` 展示双栏或上中下布局，星标作为置顶机制。

## 监听与接口

通过 preload 列目录、打开文件夹及订阅工作区事件。`src/main/workspace-watch-manager.ts` 监听所订阅根目录本身；渲染层收到事件后重新加载已展开目录并保留旧缓存，避免刷新闪空。

自身的新建、重命名与删除会在主进程登记 `recordSelfWrite` 抑制工作区监听广播，渲染层在操作成功后主动刷新受影响目录。单文件监听无需特殊处理：重命名的标签路径更新先于防抖事件到达，删除对应的标签同步关闭。

当前不做递归监听，不能承诺任意深层目录变化都即时可见。自身保存的目录事件有短期抑制，少量同期外部变化可能延迟到后续刷新。

## 必须保持的约束

根变化时解除旧订阅；同一会话恢复根时保留对应展开状态。路径归属与 Windows 路径比较通过共享逻辑处理，不用简单字符串前缀代替目录边界判断。文件树展示范围与打开流程的扩展名白名单同源（`openable-document`），两端口径不得分叉。失效最近记录经访问核验后清理；上中下布局清除最近记录时保留星标。

基础操作约束：

- 新建与重命名不得覆盖既有文件；重命名仅作用于普通文件（目录一律拒绝，防止批准的工作区目录被整体改名移出边界），重命名前必须显式检查目标存在性，Windows 上需放行仅大小写差异的改名。
- 删除一律进入系统回收站（`shell.trashItem`），不直接销毁；目标必须是已批准根的严格子级（工作区根本身不可删）。文件删除携带打开标签的磁盘基线，存在未处理的外部版本时拒绝；目标内有未保存修改的打开标签时，确认框必须警示内容丢失，删除执行期间暂停受影响标签的自动保存。
- 重命名与删除不自动改写其他文档中的相对链接或图片路径；产品不做全库索引，点击失效链接时按既有"文件不存在"流程提示。重命名同样不迁移 `<原名>.assets` 附件目录、不改写正文引用——显示不受影响，但按新名另存副本时找不到旧附件目录属已知边界（用户在资源管理器改名同样触发），改进方向见待办"按正文引用收集另存附件"。
- 三项操作的授权边界由主进程 `workspace-authorization.ts` 维护：授权只来自用户可感知的可信途径（文件夹对话框、打开文件对话框、另存为对话框、最近菜单与文件关联/命令行的推送打开、启动时从可信最近记录播种），渲染层任意可控的 IPC（`file:read`、`workspace:watch`）不产生授权，其写入的最近记录条目不带可信标记、不参与播种。判定与登记前先 `resolve` 再 `realpath`（防 `..` 穿越与符号链接/目录联接绕过）且不授权盘符根。由此产生的已知边界：经文档内链接跳转或拖放到窗口打开的文件，其所在文件夹当次会话内未获授权，右键操作会被拒，需显式打开文件夹或经可信途径重新打开——拖放事件只存在于渲染进程，主进程无法验证其来源，不为其开授权通道。
- 重命名文件有打开标签时携带标签的磁盘基线，主进程核对磁盘修改时间一致才放行；存在未处理的外部版本时返回 conflict，由渲染层提示先处理外部改动，防止重命名洗掉基线后下次保存静默覆盖。
- 删除执行期间（移入回收站完成前）新变脏的标签不随删除静默关闭，保留标签供「另存为」救回内容并提示用户。
- 已知时序边界（评审确认不做）：删除完成的瞬间尚在编辑器 0.2 秒延迟上报窗口内的输入，内容快照看不到，仍可能随标签关闭丢失；删除执行期间新打开的目标内文档会随删除关闭。两者都要求网络盘等慢速回收站与特定输入时机叠加，出现后以最近记录的失效清理与「另存为」兜底，不再为此加锁或冻结编辑器。启动播种按最近记录路径的当前真实位置授权，两次启动之间路径被替换为链接时按新位置恢复——能改写本地文件系统的主体本就不需要借本应用造成破坏。
