# Markdown 兼容性回归

本说明用于检查 InkMark 对当前已支持 Markdown 语法的显示、编辑和保存是否稳定。它不是功能规划，也不记录开发进度；每次编辑器相关改动后，直接按这里的固定步骤验证同一份样例。

## 什么时候执行

出现以下任一改动时执行完整回归：

- 升级 Milkdown、CommonMark、GFM 或编辑器插件。
- 修改 Markdown 解析、序列化、剪贴板、图片、任务列表或源码模式。
- 修改标签切换、文件加载、保存、外部刷新等可能替换编辑器内容的流程。

## 验证步骤

1. 用 InkMark 打开临时副本，保持在所见即所得模式。
2. 按下表逐项检查显示结果，确认没有内容消失、结构串层或不可编辑。
3. 按样例末尾“回归操作区”的要求完成编辑。
4. 保存文件，切换到源码模式，确认 Markdown 结构与编辑结果正确。
5. 关闭文件后重新打开，再次检查所见即所得模式和源码模式。
6. 若本次改动涉及标签、外部文件刷新或图片，再分别执行一次切换标签、外部修改后返回窗口、粘贴或拖入图片的相关操作。

## 检查清单

| 类别       | 通过标准                                                       |
| ---------- | -------------------------------------------------------------- |
| 标题       | H1–H6 层级正确，正文没有被并入标题，保存后级别不变             |
| 段落与换行 | 相邻段落保持分隔；软换行和显式换行不吞字、不合并列表           |
| 强调       | 粗体、斜体、粗斜体、删除线和行内代码范围正确，可继续输入和删除 |
| 引用       | 单层与嵌套引用层级正确，引用内可包含强调和列表                 |
| 链接       | 行内链接、带标题链接和自动链接可识别，文本与地址保存后不丢失   |
| 图片       | 本地相对路径图片可显示；替代文本和标题保存后保留               |
| 代码       | 行内代码不解析内部标记；围栏代码块保留语言标记、缩进和内容     |
| 分隔线     | 分隔线独立成块，不吞并前后段落                                 |
| 普通列表   | 无序、有序列表及连续编号结构正确，保存后项目内容不丢失         |
| 任务列表   | 未完成和已完成状态正确；点击切换后源码中的 `[ ]` / `[x]` 同步  |
| 嵌套结构   | 列表嵌套、引用内列表、列表内代码块不串层                       |
| 表格       | 表头、对齐、单元格和新增行正确；保存后仍是有效 GFM 表格        |
| 转义       | 被反斜杠转义的 Markdown 符号显示为普通字符，保存后语义不变     |
| 重开       | 保存、关闭、重新打开后，内容和结构与保存前一致                 |

## 通过与失败

以下情况算通过：

- 文档语义、层级、文字、链接地址、图片路径和任务状态均保留。
- 序列化只做等价的格式规范化，例如统一列表符号、空行或表格列宽空格。

以下情况算失败：

- 内容丢失、重复或移动到错误层级。
- 保存后产生无效 Markdown，或再次打开时显示结果改变。
- 编辑一个结构时破坏相邻结构。
- 图片路径被改成绝对路径，或本地图片保存后无法再次加载。

发现失败时，在对应修复提交中写明触发操作和受影响语法；不要修改基准样例来迁就错误输出。

## 当前边界

- 当前检查范围是 CommonMark 与项目已启用的 GFM 能力。
- 下划线、文字颜色、高亮等没有标准 Markdown 语法的格式不在支持范围内，也不通过插入 HTML 实现。
- 数学公式与 Mermaid 尚未实现，不作为当前回归的通过条件。
- 不要求保存后的字节与基准文件完全一致，但要求 Markdown 语义和再次打开的结果一致。
