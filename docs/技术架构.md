# InkMark 技术架构

本文说明当前实现的分层、模块边界、数据归属和跨模块流程。产品能力与取舍以 [产品定位](./product-positioning.md) 为准；未实现的候选事项见 [待办](./TODO.md)。

## 系统分层

InkMark 使用 Electron 与 electron-vite。主进程入口为 `src/main/index.ts`，预加载入口为 `src/preload/index.ts`，渲染入口为 `src/renderer/src/main.tsx`；构建入口配置见 `electron.vite.config.ts`。

- **主进程**：管理单实例、窗口、原生菜单、文件读写与监听、附件、导出和应用更新。文件系统能力集中于这一层。
- **预加载层**：通过 `contextBridge` 暴露 `window.inkmark` 窄接口，将请求和事件转成 IPC；不承担文档状态或冲突决策。
- **渲染层**：React 组织界面，Zustand 保存标签和设置状态，Milkdown 提供所见即所得编辑，CodeMirror 6 提供源码编辑及外部改动审阅。
- **共享层**：`src/shared/` 保存跨进程类型、语言资源与纯逻辑，不依赖 Node 或 DOM。涉及本地路径解析及文件访问的操作留在主进程。

主窗口保留 `contextIsolation: true`、`nodeIntegration: false` 和 sandbox。主进程对 IPC 请求检查可信发送方及参数；新增能力须同步维护预加载接口和 `src/renderer/src/types/index.ts` 中的声明。渲染层不能直接访问 Node 文件系统。

## 状态与数据归属

| 数据                                     | 当前归属                                  | 生命周期与约束                                     |
| ---------------------------------------- | ----------------------------------------- | -------------------------------------------------- |
| 当前正文                                 | `useStore.tabs[].sourceContent`           | 文档正文的单一真源；保存和导出读取此内容           |
| 文件路径、修改时间、未保存与外部更新标志 | `useStore.tabs[]`                         | 按标签管理；保存成功或重载后更新，取消不能视为成功 |
| 选区、撤销与编辑器内部状态               | Milkdown / CodeMirror、`editorStateCache` | 按标签及模式隔离；正文匹配才恢复，关闭时清理       |
| 大纲、字数与滚动位置                     | 标签字段及相关 Hook                       | 大纲和字数由当前文档派生，不建立独立正文副本       |
| 磁盘基线与待注入审阅块                   | `review-store.ts`                         | 按标签保存于内存；审阅期间固定版本，关闭时清理     |
| 已注入审阅块                             | CodeMirror 审阅扩展                       | 未决新增文本属于装饰层，不属于正文                 |
| 文件树根、目录缓存和展开状态             | `useFileTree`                             | 当前运行会话内维护；目录数据通过 IPC 获取          |
| 设置                                     | `settings.ts` 与 store                    | 渲染层 `localStorage` 持久化；校验、迁移后使用     |
| 窗口、主题启动值、最近记录、对话框位置   | 主进程 userData 文件                      | 主题启动值是首帧用的副本，渲染层加载设置后再次同步 |
| 更新进度与状态                           | 主进程更新服务                            | 通过 IPC 查询与推送；渲染层展示并触发用户操作      |

标签正文、编辑器缓存与审阅结果不提供崩溃恢复，也不恢复上次打开的标签集合。设置和最近记录的持久化不等于文档恢复。

## 主要数据流

### 打开与编辑

原生菜单、文件关联、最近记录、文件树及文档链接进入统一打开流程。可打开的文档类型由 `src/shared/openable-document.ts` 统一维护：Markdown 文件按用户偏好使用两种编辑模式，纯文本与代码文件固定源码模式；超过 10 MB 或非 UTF-8 编码的文件拒绝打开并提示原因。主进程稳定读取正文与修改时间，渲染层创建或激活标签，设置 `sourceContent` 及磁盘基线，再装入当前编辑模式。编辑器的变更同步回标签正文并更新未保存状态、大纲与字数。

两种编辑器都是正文的编辑投影，各自保存内部状态；切换标签或模式时只恢复与当前正文匹配的缓存，避免旧状态覆盖新内容。Milkdown 通知可能延迟，审阅入口会补齐尚未上报的真实编辑，并阻止隐藏编辑器的迟到通知覆盖审阅正文。

### 普通保存与关闭

`useFile` 读取标签正文，通过 preload 请求主进程保存。普通保存根据已知修改时间发现冲突；保留并覆盖须经过明确选择。原文件采用同目录临时文件加替换写入，并标记自身写入以避免重复外部更新提示。另存时由图片模块复制关联附件。

自动保存可选，默认关闭；开启后仅处理已保存且有修改的文档，延迟 3 秒，审阅会话期间暂停。关闭标签、关闭窗口和安装更新均需处理未保存内容，取消或失败不能继续按成功关闭。

### 外部修改与审阅

单文件监听及文件状态检查发现更新后，干净文档显示重新加载或逐项审阅入口，有未保存修改的文档进入冲突选择。不能静默覆盖人工修改。

逐项审阅固定一轮磁盘版本并切换至源码模式：按行生成改动块，决定后物化到 `sourceContent`，未决块仅存在于装饰层。保存前由主进程核验正文与修改时间；版本变化或无法核验时仅允许创建新副本。该保护不是文件锁，不承诺外部持续写入时绝对无冲突。

### 图片、导航与导出

图片由主进程存储，正文只引用相对路径；文档链接先解析目标，再复用打开流程。文件树读取目录、跟随活动文件并提供新建、重命名与回收站删除；操作成功后由应用自身同步打开标签的路径与磁盘基线，删除不自动改写其他文档中的链接。文件树操作不承担正文状态。导出读取当前标签正文，经主进程生成 HTML 或在隐藏窗口打印 PDF，不从可见编辑器 DOM 截取排版；导出与逐项审阅仅面向 Markdown 文档，纯文本与代码文件不参与。

## 设计约束与验证入口

- 新功能先核对产品边界，不扩展为知识库或私有文档格式。
- Markdown 解析和序列化要求语义保留，不承诺字节一致；相关验证见 [兼容性回归](./markdown-compatibility.md)。
- 主题分为外壳与内容，原生标题栏同步另有约束，见 [主题架构](./theme-architecture.md)。
- 依赖升级按 [依赖管理](./dependency-management.md) 执行；脚本和依赖版本以 `package.json` 为准。
- 文档更新在所属模块入口或既有专题原位进行；历史评估与现行实现须区分，不把待办写成已实现能力。
