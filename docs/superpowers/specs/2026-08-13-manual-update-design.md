# Windows 手动一键更新设计

## 目标

InkMark 在现有“帮助 → 检查更新...”入口中提供完整的手动更新闭环。应用不在启动时或后台定时检查更新，不经用户确认不下载，不经用户确认不重启安装，也不在退出时自动安装。

本设计与 Windows 安装范围迁移分开实现，但下载完成后使用同一套 NSIS 安装器，因此安装范围保持、旧程序清理、按需提权和用户数据保留规则以 [Windows 安装范围与迁移设计](./2026-08-13-windows-installer-migration-design.md) 为准。

## 用户操作流程

### 检查

1. 用户点击“帮助 → 检查更新...”。
2. 更新对话框进入“正在检查更新”状态。
3. 若没有新版，显示当前版本和“当前已是最新版本”。
4. 若检查失败，显示可理解的错误信息，并保留“重新检查”和“查看发布页”。
5. 若有新版，显示当前版本、最新版本和“下载更新”按钮；此时不会自动下载。

### 下载

1. 用户点击“下载更新”后才开始下载。
2. 对话框显示下载进度、已下载大小和总大小；下载期间用户可关闭对话框并继续编辑。
3. 关闭对话框不会取消下载。再次进入“检查更新”时显示当前下载进度。
4. 下载失败时保留当前应用版本，显示失败原因，并允许重试或打开发布页手动下载。
5. 同一时间只允许一个检查或下载任务，重复点击不得发起重复请求。

### 安装

1. 下载完成后，对话框显示“重启并安装”和“稍后安装”。
2. “稍后安装”只关闭对话框。InkMark 不在退出时自动安装，也不在下次启动时自动安装。
3. 已下载更新在当前会话中保持可用；用户再次打开更新对话框时，直接显示“更新已下载”。若应用重启后更新包仍由更新组件确认有效，也显示同一状态，否则重新检查。
4. 用户点击“重启并安装”后，先走 InkMark 现有的窗口关闭保护：逐个处理未保存文档和正在写入的图片。
5. 只有关闭保护完整通过，主进程才调用更新组件重启并安装；用户取消保存、保存失败或图片仍在写入时，不退出也不安装。

## 技术方案

### 更新组件

使用 `electron-updater` 的 NSIS 更新能力，不使用 Electron 内置 `autoUpdater`。当前应用由 electron-builder 的 NSIS target 打包，发布流程已上传 `.exe`、`.exe.blockmap` 和 `latest.yml`，与 `electron-updater` 的更新协议直接匹配。

配置约束：

- `autoDownload = false`：发现新版后等待用户点击下载。
- `autoInstallOnAppQuit = false`：普通退出绝不自动安装。
- 仅在 `app.isPackaged` 且 Windows 正式安装版中启用下载与安装；开发模式返回明确的不可用状态，不发起更新请求。
- 使用 electron-builder 写入安装包资源的 `app-update.yml` 和 GitHub provider 配置，不在代码中手写下载 URL。
- 不使用 GitHub `latest release` REST 请求承担下载与校验；更新元数据、安装包选择、散列校验和差分下载统一交给 `electron-updater`。

### 模块边界

新增主进程更新服务，负责：

- 维护唯一的更新状态机；
- 订阅 `electron-updater` 事件；
- 执行检查、下载和安装命令；
- 将经过收窄的状态推送给可信渲染进程；
- 屏蔽底层错误中的本地路径、请求细节等不适合直接展示的信息。

预加载层只暴露窄接口：

- 获取当前更新状态；
- 手动检查；
- 手动开始下载；
- 请求重启安装；
- 订阅状态变化。

渲染层更新对话框只展示状态和发出用户命令，不直接访问网络、文件系统或更新组件。

### 状态模型

更新服务至少包含以下互斥状态：

- `idle`：尚未检查；
- `checking`：正在检查；
- `latest`：当前已是最新版；
- `available`：发现新版，等待用户下载；
- `downloading`：正在下载，并携带进度；
- `downloaded`：下载完成，等待用户安装；
- `error`：检查或下载失败，可重试；
- `unsupported`：开发模式或非 Windows 安装版，不执行更新。

检查和下载命令必须根据当前状态判断是否允许执行，防止重复检查、重复下载或未下载完成就安装。

## 与关闭保护的衔接

现有关闭流程由渲染进程掌握所有标签页的未保存状态，主进程不能直接绕过它调用 `quitAndInstall()`。因此增加一次明确握手：

1. 更新对话框请求准备安装；
2. 渲染进程调用现有关闭保护，但通过“为更新退出”路径执行；
3. 所有文档处理完成后，渲染进程向主进程确认可以安装；
4. 主进程标记更新退出状态并调用 `quitAndInstall()`；
5. 普通窗口关闭仍走原有逻辑，不会误触发安装。

关闭保护必须返回明确成功或取消结果，不能先关闭窗口再决定是否安装。

## 发布约束

- `package.json` 增加明确的 GitHub publish provider，仓库固定为 `lvtian-bot/InkMark`。
- Release workflow 继续上传安装包、`.blockmap` 和 `latest.yml`，并在发布后验证三类产物均存在。
- `package.json`、Git 标签、`latest.yml` 中的版本必须一致。
- 正式验证必须使用已安装的旧版本检查一个更高版本；开发构建和未安装的解压目录不算通过。
- 当前未配置 Windows 代码签名。首次下载或更新安装时仍可能出现“未知发布者”提示，这属于已知发布风险，不能在交付说明中声称已经解决。

## 错误处理

- 无网络、GitHub 不可用或元数据异常：显示检查失败，允许重新检查。
- 下载中断或校验失败：进入错误状态，不执行安装，允许重新下载。
- 发布缺少匹配架构的安装包或 `latest.yml`：显示更新暂不可用，并提供发布页入口。
- 下载完成后安装包不可用：回到可重试状态，不退出应用。
- 用户取消未保存文档处理：保持 `downloaded` 状态，继续使用应用。
- `quitAndInstall()` 调用异常：显示安装启动失败，应用保持运行；不得把普通退出标记留在错误状态。

## 测试与验收

### 自动测试

- 更新状态机允许和拒绝的命令转换。
- 下载进度归一化和错误信息收窄。
- 开发模式不检查、不下载、不安装。
- 重复点击检查或下载只产生一次底层调用。
- `downloaded` 状态下“稍后安装”不触发退出。
- 关闭保护取消时不调用安装；通过时只调用一次。
- preload 接口参数校验、可信发送方检查和监听释放。

### 安装版人工验收

使用旧版本和新版本两个正式安装包，通过 GitHub Release 验证：

1. 启动应用后没有自动更新请求和提示。
2. 手动检查无新版、发现新版和网络失败三种状态。
3. 发现新版后不会自动下载。
4. 下载进度可见，关闭并重新打开对话框后状态连续。
5. 选择“稍后安装”后，普通退出和再次启动均不自动安装。
6. 有未保存文档时点击“重启并安装”，保存、放弃和取消三条路径行为正确。
7. 更新完成后版本号正确，设置和最近文件保留。
8. 分别验证当前用户安装和所有用户安装，更新后安装范围不改变。
9. 与安装迁移规格联合验证两个安装范围之间的切换，最终不产生双份安装。

## 不在本次范围

- 启动时或后台定时检查更新。
- 未经用户点击自动下载。
- 退出时或下次启动时自动安装。
- 更新渠道、灰度发布、降级安装和跨平台更新。
- Windows 代码签名采购与证书管理。
