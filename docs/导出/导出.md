# 导出

## 职责与边界

提供当前单篇文档的 HTML / PDF，用于日常分享和打印。导出生成独立文件，不改变 Markdown 源文件；不提供 Word、专业出版模板或复杂排版控制。

## 当前流程

`src/renderer/src/hooks/useExport.ts` 从活动标签获取 `sourceContent`、标题和源路径，通过 preload 提交导出请求。有未决审阅块时拦截，避免导出尚未决定的结果；模块级防护阻止重复并发导出，较慢操作显示进度提示。

主进程 `src/main/index.ts` 校验请求并选择目标，`export-document.ts` 使用 remark / rehype 将 Markdown 渲染为 HTML：CommonMark、GFM、frontmatter 与共享宽松换行语义保持一致。原始 HTML 按文本处理，不作为活动脚本执行。

- HTML 使用内嵌样式和可读取的本地图片数据，生成单文件；远程图片仍保留远程引用，不能保证离线可见。
- PDF 将打印用 HTML 写入临时文件，由 `export-pdf.ts` 在隐藏且隔离的窗口中加载并 `printToPDF`，当前使用 A4、背景打印和标题书签大纲。结束或失败时销毁窗口并清理临时文件。

## 状态与约束

导出状态只负责进度和重复操作防护，正文仍归标签。导出使用独立的浅色 GitHub 排版，不复制可见编辑器的 DOM、主题或全部排版设置。未保存文档可导出，但无源路径时相对本地图片不能按文档目录解析。

构建时主进程使用的 `github-markdown-css` 原始样式和 ESM-only 的 `remark-frontmatter` 有打包约束，见 `electron.vite.config.ts`；不可只验证开发环境就改变外部化策略。

验证入口：`src/main/export-document.test.ts`、`src/shared/export-document.test.ts`；PDF 版面和图片加载需在能够可靠操作应用的环境实际核验。整体关系见 [技术架构](../技术架构.md)。
