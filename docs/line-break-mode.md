# 换行行为（宽松换行）

## 背景

所见即所得模式最初遵循标准 CommonMark 语义：段内单换行渲染为空格，回车新起段落。单换行在视觉上被吞掉不符合直觉，也难以对齐 Obsidian 等现代工具的表现。

## 决策过程

- 2026-09-15：定稿双模式方案（Word 模式回车即换行 / 标准 Markdown 模式）并实现，设置项全局切换；正文键位改为回车插换行、连续两次回车分段。
- 2026-09-16：确认双模式解释成本高于收益，**移除模式设置，宽松换行成为唯一显示语义**；随后试用中确认回车插换行与块间空隙光标（gapcursor）属于过度设计，**回车键位回到默认的「新起段落」，相关键位插件与 gapcursor 移除**。各阶段实现均可在 git 历史检索（`strictLineBreaks`、`line-break-keymap`、`gap-cursor`）。

## 最终行为

| 操作             | 行为                                             |
| ---------------- | ------------------------------------------------ |
| 正文回车         | 新起段落，源码以空行分隔（Milkdown 默认键位）    |
| Shift+Enter      | 换行，源码为单个换行符，视觉紧凑                 |
| 单换行的显示     | 换行，普通行距（宽松语义，与 Obsidian 默认一致） |
| 空行的显示       | 顶层段落间距，约一个空行的高度并随行距档位缩放   |
| 列表项内回车     | 新列表项（默认键位）                             |
| 表格单元格内回车 | 跳格/加行，格内换行落盘 `<br>`（见既有表格定制） |

行距分三档：段内换行只有正常行距；列表项（含待办）之间为行高加列表项间距（默认 0.3em）；段落之间为段落间距（默认 0.6em，与最初版本一致）。段落间距与列表项间距是设置里的排版数值参数（限定范围，见 `src/renderer/src/typography.ts`），不再写死。

## 语义与已知影响

- 源码模式是纯文本编辑，回车永远插入换行符，与换行语义无关。
- 严格渲染器（GitHub README、VS Code 默认预览）按 CommonMark 会把单换行合并为空格：InkMark 保存的单换行内容在这类环境显示为同段。
- 硬折行风格的外部文档（一段手动折成多行）打开后每一折行都显示为换行。
- 文件不记录任何换行语义标记；同一文件在严格渲染器与 InkMark 间的显示差异是预期行为。

## 验收要点

- 通过 [markdown-compatibility.md](./markdown-compatibility.md) 中“段落与换行”及重开一致性场景。
- 回车分段、Shift+Enter 换行、退格合并均为默认键位，无自定义拦截。
- 外部文档打开、编辑、保存，文字与结构无损；导出 HTML/PDF 的换行渲染与编辑器一致。
